# 访问统计接口文档

## 1. 概述

- 服务地址：`http://{host}:10010`
- 数据来源：原始明细表 `access_log` + 预聚合表（小时统计、URL 每日统计），查询接口只读预聚合表
- 统一响应体：`{"code": Integer, "msg": String, "data": T}`
- 成功时 `code=200`、`msg="操作成功"`；业务异常同样返回 HTTP 200，通过 `code` 区分
- 时间参数格式统一为 `yyyy-MM-dd HH:mm:ss`，按服务端时区（Asia/Shanghai）解析
- 查询时间跨度最大 **40 天**（`end - start <= 40 天`，且 `end > start`）

### 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/access-log` | 上报一条访问日志 |
| GET | `/admin/access-log/url/daily` | 按 URL 分组，返回区间内每个 URL 每天的访问次数（Top 30 URL） |
| GET | `/admin/access-log/url/total` | 返回区间内每个 URL 的总访问次数（Top 15 + 其他） |
| GET | `/admin/access-log/hourly` | 返回区间内每小时的总访问量（所有 URL 聚合） |
| GET | `/admin/access-log/daily` | 返回区间内每天的总访问量（所有 URL 聚合） |

### 错误码

| code | msg | 触发场景 |
|---|---|---|
| 200 | 操作成功 | 正常返回 |
| 10019 | 开始时间不能大于结束时间 | `end <= start` |
| 10020 | 日期范围过大 | `end - start > 40 天` |
| 500 | 异常信息 | 其他服务端异常 |

错误示例：

```json
{
  "code": 10020,
  "msg": "日期范围过大",
  "data": null
}
```

## 2. 上报访问日志

`POST /access-log`

请求头由服务端读取 `Referer`、`User-Agent` 等，客户端只需传 JSON：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| url | string | 是 | 访问的页面路径，建议不带结尾斜杠 |
| region | string | 否 | 地区，为空时记为 `Unknown` |
| device | string | 否 | 设备类型，为空时由 User-Agent 解析 |
| browser | string | 否 | 浏览器，为空时由 User-Agent 解析 |
| os | string | 否 | 操作系统，为空时由 User-Agent 解析 |

请求示例：

```
POST http://localhost:10010/access-log
Content-Type: application/json

{
  "url": "/tools/essence-calculator",
  "region": "CN"
}
```

响应示例：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": null
}
```

## 3. 按 URL 分组的每日访问量

`GET /admin/access-log/url/daily`

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| start | query | string | 是 | 开始时间，`yyyy-MM-dd HH:mm:ss` |
| end | query | string | 是 | 结束时间，`yyyy-MM-dd HH:mm:ss` |

说明：

- 返回区间内累计访问量最高的 **Top 30 URL**，按累计访问量降序
- 每个 URL 的 `data` 按天列出，区间内每一天都会出现，无数据补 0
- `period` 格式为 `yyyy-MM-dd`

请求示例：

```
GET http://localhost:10010/admin/access-log/url/daily?start=2026-10-30%2000:00:00&end=2026-11-01%2000:00:00
```

响应示例：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {
      "url": "/tools/essence-calculator",
      "data": [
        {"period": "2026-10-30", "count": 120},
        {"period": "2026-10-31", "count": 98},
        {"period": "2026-11-01", "count": 121}
      ]
    },
    {
      "url": "/characters",
      "data": [
        {"period": "2026-10-30", "count": 66},
        {"period": "2026-10-31", "count": 70},
        {"period": "2026-11-01", "count": 64}
      ]
    }
  ]
}
```

## 4. 每个 URL 的总访问量

`GET /admin/access-log/url/total`

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| start | query | string | 是 | 开始时间，`yyyy-MM-dd HH:mm:ss` |
| end | query | string | 是 | 结束时间，`yyyy-MM-dd HH:mm:ss` |

说明：

- 按区间内累计访问量降序，前 15 个 URL 单独返回
- 其余 URL 合并为一条 `{"url":"其他","totalCount":...}`
- URL 总数不超过 15 时不返回 `其他`
- **不返回「访问总和」条目**；需要总量时由客户端累加 `data` 中所有 `totalCount`（含 `其他`）

响应示例：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {"url": "/tools/essence-calculator", "totalCount": 339},
    {"url": "/characters", "totalCount": 200},
    {"url": "/weapons", "totalCount": 88},
    {"url": "其他", "totalCount": 12}
  ]
}
```

## 5. 每小时总访问量

`GET /admin/access-log/hourly`

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| start | query | string | 是 | 开始时间，`yyyy-MM-dd HH:mm:ss` |
| end | query | string | 是 | 结束时间，`yyyy-MM-dd HH:mm:ss` |

说明：

- 所有 URL 聚合后的每小时访问量
- 区间内每个整点都会返回，无数据补 0
- `period` 格式为 `yyyy-MM-dd HH:00`

响应示例：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {"period": "2026-11-02 08:00", "count": 21},
    {"period": "2026-11-02 09:00", "count": 33},
    {"period": "2026-11-02 10:00", "count": 17}
  ]
}
```

## 6. 每天总访问量

`GET /admin/access-log/daily`

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| start | query | string | 是 | 开始时间，`yyyy-MM-dd HH:mm:ss` |
| end | query | string | 是 | 结束时间，`yyyy-MM-dd HH:mm:ss` |

说明：

- 所有 URL 聚合后的每日访问量，与「URL 总量」接口使用同一张日统计表，口径一致
- 区间内每一天都会返回，无数据补 0
- `period` 格式为 `yyyy-MM-dd`

响应示例：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {"period": "2026-11-01", "count": 456},
    {"period": "2026-11-02", "count": 123}
  ]
}
```

## 7. 数据口径与时效

- **统计粒度**：小时统计与 URL 每日统计均由定时任务写入预聚合表，接口不实时扫描 `access_log`
- **小时数据**：每 20 分钟统计一次上一个完整小时，最近 1 小时最多延迟 20 分钟
- **当天数据**：每 30 分钟重刷一次当天 URL 访问量，当天数据最多延迟 30 分钟
- **昨日数据**：每天 0:00、8:00、16:00 重新统计，避免跨天边界遗漏
- **URL 归一化**：统计时去除 URL 结尾斜杠，`/a/` 与 `/a` 视为同一路径
- **单日 URL 上限**：每天按访问量只保留 Top 200 个 URL，跨区间查询时排名靠后的 URL 不会出现
- **历史回填**：应用启动时自动回填最近 7 天，之后每天 3:30 补偿回填缺失周期
- **查询窗口**：接口允许查询 40 天，但当前仅回填 7 天，超出回填范围的历史日期会以 0 返回
